# خطة تطوير صالون H&M — نظام حجوزات كامل

## الوضع الحالي (ملخص)
- TanStack Start + Supabase + Tailwind (مشروع Lovable).
- جدول واحد `bookings` + `user_roles`. حالة: `booked / done / cancelled`.
- مواعيد كل 20 دقيقة، 12:00–22:00، الاثنين عطلة — **مكتوبة hardcoded** في `src/lib/slots.ts` وفي دالة SQL `create_booking` (`mins % 20`).
- تيلجرام: رسالة فقط، والعميل (المتصفح) هو اللي بينادي `notifyBooking` → ممكن تضيع.
- لوحة الحلاق: حجوزات اليوم، تم/إلغاء، زبون بدون حجز، QR.
- مشاكل: كلمة سر ثابتة `Admin12345`، لا حد للحجوزات (أي حد بيقدر يعبّي اليوم)، لا موافقة، لا أرشيف، لا إعدادات.

## المرحلة 1 — قاعدة البيانات (الأساس)

### جدول `settings` (صف واحد)
| حقل | افتراضي |
|---|---|
| `booking_enabled` (on/off) | true |
| `pause_until` (استراحة لحد وقت معيّن) | null |
| `pause_reason` | null |
| `service_minutes` | 20 |
| `buffer_minutes` (راحة بين الحجوزات) | 5 |
| `open_min` / `close_min` | 720 / 1320 |
| `days_off` (مصفوفة أيام) | {1} = الاثنين |
| `booking_window_days` | 7 |
| `max_party_size` | 4 |
| `max_bookings_per_device_24h` | 2 |
| `auto_approve` | false (موافقة يدوية) |
| `min_notice_minutes` (أقل مدة قبل الموعد) | 15 |

### تعديل `bookings`
- `status`: `pending → approved → done` / `rejected` / `cancelled` / `no_show`.
- `party_size int` (1–4) + `party_names text[]` اختياري (أب + أولاده).
- `end_at timestamptz` = البداية + (عدد الأشخاص × 25 دقيقة).
- `device_id text`, `phone_norm text` (رقم موحّد 07xxxxxxxx), `ip_hash text`.
- `public_token uuid` → رابط للزبون يشوف حالة حجزه / يلغيه.
- `decided_at`, `decided_by`, `reject_reason`, `admin_note`.
- **استبدال** الـ unique index على `start_at` بـ exclusion constraint على `tstzrange(start_at, end_at)` (امتداد `btree_gist`) لمنع أي تداخل — ضروري لحجز العائلة.

### جداول جديدة
- `blocks` (فترات مسكّرة يدويًا: من–إلى + سبب) — للاستراحات المجدولة والإجازات.
- `blocked_phones` / `blocked_devices` (قائمة سوداء للمزعجين).
- `audit_log` (مين وافق/رفض/غيّر إعداد ومتى).

### دوال SQL
- `get_public_state(_day)` → الإعدادات العامة + الفترات المحجوزة + هل النظام مسكّر/بالاستراحة. بدون بيانات شخصية.
- `create_booking(name, phone, start, party_size, device_id, party_names)` — كل التحقق على السيرفر:
  1. النظام شغّال ومش باستراحة، مش يوم عطلة، داخل ساعات الدوام.
  2. البداية على شبكة الـ 25 دقيقة، والمدة كاملة داخل الدوام ولا تتقاطع مع `blocks`.
  3. **حد الجهاز**: عدد الحجوزات الفعّالة لنفس `device_id` **أو** نفس `phone_norm` **أو** نفس `ip_hash` خلال آخر 24 ساعة < 2. وإلا رسالة: "وصلت للحد، بتقدر تحجز بعد [الوقت]".
  4. القائمة السوداء.
  5. الحالة `pending` أو `approved` حسب `auto_approve`.
- إشعار تيلجرام **من السيرفر** بعد الإدخال مباشرة (مش من المتصفح).

> ملاحظة صريحة: `device_id` (localStorage + cookie) ممكن ينمسح. لهيك الحد مربوط بالجهاز + الرقم + IP مع بعض. حماية أقوى لاحقًا (اختياري): تأكيد الرقم بكود OTP.

## المرحلة 2 — المواعيد: 20 + 5
- الحلاقة 20 دقيقة + 5 راحة = خانة كل 25 دقيقة: 12:00، 12:25، 12:50 ... آخر موعد 21:35 (24 موعد باليوم).
- الأرقام من `settings` بس — تغييرها من الأدمن بدون كود.
- حجز عائلة 3 أشخاص = 3 خانات متتالية (75 دقيقة). المواعيد اللي ما بتكفي للعدد بتظهر مقفولة.
- `src/lib/slots.ts` يصير يقرأ الإعدادات بدل الثوابت، ونفس المنطق بالـ SQL.

## المرحلة 3 — صفحة الزبون
1. بانر حالة: مفتوح / "همام باستراحة لحد 4:30" / "الحجز متوقف حاليًا" / "متاح الآن".
2. اختيار **عدد الأشخاص** (1–4) قبل الوقت، مع خانات أسماء اختيارية لكل شخص.
3. اليوم ← الوقت (يتفلتر حسب العدد).
4. الاسم + الرقم ← تأكيد.
5. شاشة نتيجة: "طلبك قيد المراجعة" أو "تم التأكيد" + رابط حالة الحجز (يتحدّث مباشرة realtime) + زر إلغاء + إضافة للتقويم (.ics).
6. رسالة واضحة عند الوصول للحد اليومي مع الوقت المتبقي.

## المرحلة 4 — لوحة الأدمن الكاملة (`/barber`)
تبويبات أسفل الشاشة (موبايل أولًا):

| التبويب | المحتوى |
|---|---|
| **الآن** | سويتش كبير ON/OFF للنظام · أزرار استراحة سريعة (30د / 1س / 2س / 3س / مخصص) مع عدّاد تنازلي · الزبون الحالي والتالي · زبون بدون حجز |
| **الطلبات** | الحجوزات المعلّقة: ✅ موافقة / ❌ رفض (مع سبب) · موافقة على الكل · شارة بعدد الطلبات |
| **الجدول** | يوم/أسبوع: تم · غياب · إلغاء · نقل موعد · ملاحظة · اتصال/واتساب بضغطة · إضافة فترة مسكّرة |
| **الأرشيف** | كل الحجوزات القديمة: بحث بالاسم/الرقم، فلترة بالتاريخ والحالة، تصدير CSV |
| **الإحصائيات** | بسيطة: زبائن هالأسبوع/الشهر · نسبة الحضور/الغياب/الإلغاء · أكثر الساعات والأيام ازدحامًا · زبائن جدد مقابل دائمين · متوسط عدد الأشخاص |
| **الإعدادات** | كل حقول `settings` · أيام العطل · القائمة السوداء · تغيير كلمة السر |

- الأرشيف = نفس الجدول (`start_at < اليوم`)، مش نسخ بيانات — أسرع وما بيضيع شي. View `bookings_archive` + دالة `get_stats(from, to)`.

## المرحلة 5 — تيلجرام (أقوى)
- رسالة الحجز الجديد فيها **أزرار**: ✅ موافقة · ❌ رفض · 📞 اتصال — عن طريق webhook (`/api/telegram`) يتحقق من secret token و chat_id.
- أوامر: `/pause 2` (استراحة ساعتين) · `/resume` · `/off` · `/on` · `/today` (جدول اليوم) · `/stats`.
- ملخص يومي تلقائي عند فتح الصالون (cron).
- تذكير لهمام قبل كل موعد بـ 5 دقائق (اختياري).
- تنبيه لو في طلبات معلّقة أكثر من 10 دقائق.

## المرحلة 6 — الأمان والجاهزية
- إلغاء كلمة السر الثابتة `Admin12345` وتغييرها لكلمة قوية + خيار تغييرها من الإعدادات.
- rate limit على `create_booking` (لكل IP بالدقيقة).
- سياسات RLS للجداول الجديدة (الأدمن فقط يقرأ/يكتب، العام عبر دوال security definer فقط).
- اختبارات Vitest لمنطق المواعيد والحدود (25 دقيقة، العائلة، حد الجهاز، الاستراحة).
- PWA: أيقونات + offline بسيط للوحة الحلاق.

## المرحلة 7 — التصميم الفخم
- هوية: أسود فحمي + ذهبي مطفي، خط عربي فاخر للعناوين (مثل Reem Kufi / Amiri) + IBM Plex Sans Arabic للنص.
- حركات ناعمة: ظهور الخانات، تأكيد الحجز، سويتش الاستراحة.
- صور/قسم عن الصالون + الأسعار + الموقع (خريطة) + زر واتساب.
- SEO محلي: Schema `HairSalon`/`BarberShop`، عنوان، ساعات الدوام.
